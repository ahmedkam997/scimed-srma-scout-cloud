# Scientific verification V2 — phase 1
Implemented a separate **trusted-adjudication** path integrated into the strict orchestrator. No threshold change, no browser/AI-supplied clearance. Two operator-provisioned distinct keys authenticate approvals of the same reconciled submission; the reviewers must independently inspect full texts, independently extract data and reconcile disagreements. HMAC is symmetric and the trusted operator can technically sign; this is not a proof of personal identity or independence. No reviewer keys are configured in hosted GitHub Actions. Do not store keys or approvals in public GitHub. A secure owner/reviewer submission transport and identity provisioning are future work.

Export the latest study-centric packet, including verification_v2.snapshot_sha256, from the dossier. Complete its reviewer_submission_template, all indexed reports (included or explicitly excluded), all competitor decisions including unclassified ones, and source-linked domain ratings. Each row must list the two actual approving reviewers. The seven independent RCT and seven extractable-outcome requirements remain. The exact outcome/definition/timepoint/measure group is independently adjudicated, with individual parallel randomization explicitly confirmed. A common-effect inverse-variance pilot supports non-boundary RR/OR, MD and LOG_HR; sparse events, SMD, cluster/crossover and other designs remain pending rather than silently misanalysed. Heterogeneity is reported, not automatically resolved by the pilot.

For NOVEL all competitor decisions must be non-overlap. UPDATE must reconstruct each overlapping review's common-effect baseline on the same outcome and scale, demonstrate independent post-cutoff trial evidence, and exceed a clinically justified threshold. Thresholds 3/5 novelty, 4/5 information gain/importance/publication, 75/100 composite, and editorial grade remain. Route-specific ratings are independent judgments with rationale, not a validated scale or publication probability. CORRECTIVE supports only a source-linked reconstruction of an incorrect effect or variance extraction using the same independent trial set and same outcome. It requires original analysis rows, an identified discrepancy, a reproduced published common-effect estimate and SE, and a clinically justified effect change. Other correction types remain pending. Other legitimate update cases (precision alone, new outcomes, different statistical models) also remain pending; the pilot is intentionally narrow. Overlapping registrations must be resolved through a future documented adjudication route, not ignored.

Operator workflow: each reviewer signs the identical reconciled submission after independent assessment using scripts/sign_scientific_adjudication.py; assemble {"submission": ...,"approvals":[...]} in a protected local directory PROJECT_ID/CANDIDATE_ID.json. Set SCIMED_TRUSTED_ADJUDICATION_DIR and SCIMED_TRUSTED_REVIEWER_KEYS_FILE (JSON reviewer -> random hex key) in a private operator environment. Neither env variable is provisioned in hosted production yet. Changed evidence/search scope invalidates signatures. A completed report is not proof of a qualified topic. Tests use explicitly synthetic data; they prove software reachability, not clinical validity.

References: Cochrane Handbook ch4,5,10,IV; MECIR C43–51; Garner et al BMJ 2016 doi:10.1136/bmj.i3507; ASReview LAB (prioritization only).

Search completeness must be independently adjudicated against the exact search-log digest; API success alone is insufficient. External numerical regression: CRAN metafor README dat.bcg 13-study table, all log RR and variances and published Q=152.2330. Only seven rows carry random allocation labels, and the example is not an eligibility or novelty test.

Joint cue triage now counts the intersection at report-group level rather than the minimum of unrelated counts. A one-time same-comparison PubMed recovery runs on resumption when comparison cues are sufficient but joint cues are not. All counts remain unconfirmed. Separate unresolved storage integrity issue: SQLite external_evidence currently keys on candidate/type/record ID without source, so source-native identifier collisions can overwrite rows; a backward-compatible key migration is required before hosted V2 deployment.

## Phase 2 storage integrity
SQLite schema v4 uses candidate + evidence type + source + native record ID as primary key. Migration is transactional, verifies row counts and flags legacy candidates; old overwritten data cannot be recovered from the surviving row. Legacy snapshots remain ineligible for V2 until fresh retrieval in a new ledger. Registry result extraction now runs even if every report has an observed registry link.

Phase 2 extraction: exact-source abstract event/denominator leads, identity-checked OA JATS raw table cells with spans and Methods snippets, explicit registry design and participant count leads. No inferred arms, no automatic trial eligibility or pooling. Hybrid BM25 and existing lexical rank via reciprocal-rank fusion prioritizes uncached competitors; no exclusion, no new AI requests. Bounded OA calls and registry calls, no negative inference from missing data.

Live source challenge: scripts/v2_phase2_live.py compares extracted count pairs against independent published DAPA-HF (PMID 31535829), DELIVER (36027570), EMPEROR-Reduced (32865377), ROLARR (29067426). Checks exact registry design and per-outcome count pairs, OA tables, and rank changes on sampled real review citations. Known labels are not input to ranking or extraction. These are retrieval/measurement controls, not a held-out complete SR reference set or a novel qualified topic.

Live initial run: CT.gov design retrieved for all four, exact participant/event pair agreement for DAPA-HF and DELIVER. Europe PMC returned ACCESS_FAILED for each article and both review searches. Added a bounded exact-PMID EFetch fallback (new PubMed variant, never overwrite other source) and independent PubMed review search fallback in the live audit. Registry result layouts are reported to distinguish unavailable results from non-count effect formats; no inferred counts from percentages.
