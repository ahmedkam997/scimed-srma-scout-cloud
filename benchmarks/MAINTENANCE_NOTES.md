# Maintenance inbox
See https://github.com/ahmedkam997/scimed-srma-scout-cloud/issues?q=is%3Aissue+is%3Aopen+%22SciMed+monitor%22 .
Monitor runs after trusted main-branch CI, worker, smoke and comparison runs, with a manual scan of latest completed runs. It uses GitHub Issues, not arbitrary model code, and deduplicates by workflow and finding code. Repeated incidents update the existing bot issue's body while retaining comments; the reviewer decides if it should be closed. Only allowlisted diagnostic codes and trusted run metadata are published; no raw logs, prompts, candidate titles, keys or database details. The monitor reads ZIP JSON without extracting files or executing artifact code. Workflow permissions: contents read, actions read, issues write. No code writes or automatic changes to scientific rules. It does not automatically wake a ChatGPT conversation; ask ChatGPT to review the inbox, or separately configure a scheduled review. References: Google SRE postmortem action items https://sre.google/workbook/postmortem-culture/ ; GitHub token permissions https://docs.github.com/en/actions/tutorials/authenticate-with-github_token ; secure workflow use https://docs.github.com/en/actions/reference/security/secure-use . Known limitation: worker failure detection uses workflow conclusion only; successful zero-qualified production runs are not monitored in this version. No unattended patch generation. 

## Worker aggregate telemetry v1
On actual discovery jobs (not idle/recheck), worker publishes a bounded aggregate JSON artifact after final storage success, or a sanitized failure category. No extra service, database access or AI calls. Records logical AI requests, observed response token totals (missing usage remains unknown), fallback/availability indicators, elapsed job time, generation/verification counts, duplicate and off-scope counts, source incompleteness, reason and opportunity categories. Counts are not independent eligible studies. Alerts: >=45 minutes elapsed; observed quota/availability pressure; three recent completed same-scope/question-type jobs with >=3 verified and zero qualified, three fresh runs with <50% generation yield, or three runs with >=50% candidate coverage blockers. These are provisional engineering thresholds, not validated performance standards. Historical artifacts are bounded and checked against trusted main-branch workflow metadata; no raw text from artifacts becomes issue content. Successful zero-yield alone is not a bug. Logical requests exclude internal HTTP retries, token usage may be partial, actual remaining quota is not measured. Source-only and idle runs intentionally have no artifact. Retention 14 days. References: https://sre.google/sre-book/monitoring-distributed-systems/ ; https://prometheus.io/docs/practices/alerting/ ; https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-04 .
